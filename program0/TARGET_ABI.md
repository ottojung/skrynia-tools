# Program 0 on the target ABI

Derivative design for owner-approved ABI 3.1 (2026-11-27). Program 0 is a
token verifier and a dumb generic proxy. No application policy, no embedded
kernel program, no production deployment.

## Entry and boundaries

The kernel calls the root export `skrynia_main(input_fd, output_fd) -> i32`.
Fixed imports use `skrynia_v3_1`; u64 buffer pointers address the caller's
exported linear memory. P0 loads the operator-selected child from
`operator/programs/root.wasm` directly into its private memory using bulk
read. It calls one `eval(code, size, invoke_selector, input_handle,
output_handle)`, with code snapshotted by the kernel before execution.
The child's single import is `p0.invoke(ctx: i32, op: i32, value: i32) -> i64`.
P0 selects its own callback from its exported indirect table. The context
and two eval handles remain opaque userland values.

## invoke protocol (coordinated with T3 before implementation)

Coordinated on board issues `vQUJZ6fZ0` (T2) and `rNTsH6jffVX9qzKbF3hf8B`
(T3); T3 confirmed the signature, selector, entrypoint and import pair
`p0`/`invoke`, and refined the op codes:

| op | name | meaning |
|---|---|---|
| 0 | GET | next inbound/reply byte (`0..255`), `-1` at EOF/none |
| 1 | PUT | append one byte to the framed descriptor request |
| 2 | FLUSH | execute the framed request; reply bytes become readable via GET |
| 3 | CB_GET | reserved; unsupported by P0 |
| 4 | CB_PUT | reserved; unsupported by P0 |
| 5 | STATUS | current relay status |

Framed requests use the existing userland i32-LE opcodes shared with T3:
`1` OPEN_DISK, `2` READ, `3` WRITE, `4` CLOSE, `5` MKDIR, `6` DELETE,
`7` RENAME, `8` OPEN_DIRECTORY, `9` NEXT_ENTRY, `10` SYNC, `11` RANDOM_FILL,
`12`/`13` userland CAS lock, `14` EXISTS, `15` EVAL. Ops 5/6/8 relay to the
existing fixed imports `mkdir`/`delete`/`open_directory`; op 7 to `rename`;
op 9 reads the entry name into private memory and returns it via the reply;
op 10 to `sync`. OPEN_DISK's trailing `u32` mode is relayed verbatim; the
gateway permits only explicit `user/` paths and the kernel confines them to the selected root. P0 itself can read its private operator files.
Descriptor handles `0`/`1` denote the per-invocation input/output streams.
The reply is `[i32 code][data]`. GET terminates each reply with its own EOF, without consuming further input. PUT and FLUSH reject an undrained reply. Frames are capped at 2 MiB; an invalid byte or overflow invalidates the whole frame. RANDOM_FILL is exactly opcode 11 followed by a little-endian u32 bit count; the reply contains the byte count and the generated bytes. Every frame must end exactly after its
declared fields: a short or trailing byte fails with INVALID before any kernel
effect. READ/WRITE/NEXT_ENTRY keep their existing chunk caps instead of
silently truncating a larger request. A READ transport error other than EOF
(`-1`) is an error reply, not EOF-like partial success.

## Per-request isolation and recovery

Every request gets a fresh root instance and private buffers. The only shared
RAM usage is the 16 one-byte owner tags at offsets 64–79 and the resource
lease at offset 80. P0 grows RAM to at least 81 bytes if needed, without
shrinking an already larger object. Owner tags are claimed by CAS and released
on request exit; the slot index identifies the lease owner, not a scratch
buffer. Authentication and private code loading occur before owner acquisition.

Ops 12/13 mediate the same absolute shared lease byte. Zero is free and
1..=16 is the owner tag. Op 12 returns 1 on acquisition or 0 on contention;
op 13 returns 0 for an owner release and -4 for non-owner/unheld release.
Every request exit, including a trapped child, reclaims only its own lease,
closes descriptors and frees the owner tag. This is userland coordination,
not a native kernel lock.

Paths, code, random output, directory entries and bulk descriptor transfers
use private buffers. The prior 2,096,000-byte executable and random-output
bound and 2 MiB frame bound remain userland protocol limits, not shared
staging capacity or kernel metering. Code loading checks EOF at the exact
limit, rejects one extra byte and closes the source on every path. RENAME
passes independent validated path buffers; no shared path-area collision.
The existing 64 KiB READ/WRITE and 4096-byte NEXT_ENTRY caps remain.
READ/WRITE repeat short transfers and preserve the userland reply encoding.
Nested eval uses private frame bytes, shares only the parent's owner tag,
cannot release its lease and cannot access its opened disk handles. Nested
handles and queues are closed/discarded on success or trap.

## Explicit blockers and non-goals

- `copy` four-argument semantics remain owner-unresolved; no `copy` import or
  guessed signature is generated. The portable fallback can now use bulk read/write; no copy import is required.
- P0 never relays a callback into a suspended P1: a synchronous P1 -> P0.eval
  relay would deadlock a P2 awaiting P1 appdata. CB_GET/CB_PUT are unsupported by P0. Callback-owning
  guests run in the in-process interpreter inside P1, which
  P0 loads into private memory and evaluates as an ordinary `_start` child.
- Framed opcodes 5-10 use the fixed 3.1 imports. Ops outside `1..=15` still return `-4` ENOTSUP.
- Old-ABI qualification evidence is historical and not acceptance of 3.1.
