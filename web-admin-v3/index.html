Skrynia v3 Administration

Native POST-only browser administration for immutable app history and atomic activation.

Configuration and security

This static admin UI requires an injected native Program 0 capability adapter (window.__skryniaV3AdminCapabilities) that performs explicit authorized binary POST operations. The UI is fail-closed without a tested adapter and does not provide server-side authorization, readiness enforcement, or transport security by itself.

Unlock encrypted browser vault

The vault access secret is used only for local browser encryption/decryption and is never sent over the network, stored in public releases, or logged.

Vault unlocked

Operator session credential

For a trusted server-side admin session/gateway or operator local secure entry only. Never a raw Program 0 bearer token and never embedded in anonymously downloaded static assets. Kept in browser session memory only while unlocked, not written to the vault/local storage/URL/query string/fragment or logged by this UI, and cleared on lock. The injected adapter is responsible for using it without leaking it.

Applications and release history

Shows every discovered application and every ready historical release loaded by the adapter. Activation/rollback performs one bounded compare-and-swap on the active release pointer only (O(1) in version count and asset bytes) with optimistic CAS state from the loaded app pointer. No release assets or application data are copied or migrated. Uncertain/lost-ack outcomes require explicit refresh and reconciliation before further activation of the affected app.
